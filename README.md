## 1. Постановка проблемы.

Задача: автоматизировать отбор семейных фотографий для экономии места на устройстве: из неструктурированного архива выделить подмножество «корректных» фото (без дефектов качества и неудачных кадров с людьми), чтобы пользователь мог перенести на новый диск только их.

Целевая аудитория: непрофильные пользователи (обычные люди), которые много фотографируют близких; не имеют технических навыков, не хотят вручную сортировать тысячи фото.

Контекст использования:

 - Пользователь загружает папку с фото
 - Система обрабатывает пакетно (batch) и формирует две папки: good/ и defective/.
 - Для спорных случаев (неоднозначные кадры) система может помечать их тегом review/ — на усмотрение пользователя.

## 2. Данные

Данные я буду брать из базы семейных и личных фотографий, а также из дополнитьльных из интернета.

Дполнительные:
 - COCO 2017 (https://www.kaggle.com/datasets/awsaf49/coco-2017-dataset);
 - Blur dataset (https://www.kaggle.com/datasets/kwentar/blur-dataset)

Всего будет несколько признаков: размытые и не размытые для первой модели, "есть люди" и "нет людей" для второй. Остальные признаки: закрытие глаз, увод взгляда, открытый рот, искривление губ - для третьей модели

## 4. Основной подход
Реализована сквозная каскадная **Pipeline-система** на базе `PyTorch` со встроенным механизмом раннего выхода (Early Exit) для оптимизации вычислений:

1. **Модель 1 (Детекция людей):** Предобученная сверточная нейросеть (CNN), возвращающая логиты классов `has_human` / `has_not_human`.
2. **Модель 2 (Оценка размытия):** Предобученная сверточная нейросеть (CNN), возвращающая логиты классов `blur` / `sharp`. 
3. **Модель 3 (Анализ геометрии лиц):** Архитектура MTCNN (`facenet-pytorch`), экспортированная в локальные веса `.pt` для автономности инференса. Алгоритм рассчитывает метрики геометрической симметрии по 5 ключевым точкам (глаза, нос, углы губ) для детекции увода взгляда (метрика EAR) и деформации улыбки (метрика MAR).

**Логика раннего выхода:** Если Модель 1 или Модель 2 фиксируют дефект (нет человека или размыто), пайплайн мгновенно прекращает работу, копирует файл в `result_#/defect` с переименованием в `defect_#` и переходит к следующему кадру, не нагружая GPU/CPU анализом лиц.

## 5. Метрики качества
Для оценки бинарной классификации пайплайна используются стандартные метрики `scikit-learn`: Accuracy, Precision, Recall, F1-Score, а также матрица ошибок (Confusion Matrix).

По результатам сквозного тестирования 167 изображений на полном пайплайне были получены следующие метрики:

```text
              precision    recall  f1-score   support

  Defect (0)       0.66      0.92      0.77        87
 Correct (1)       0.84      0.47      0.61        80

    accuracy                           0.71       167
   macro avg       0.75      0.70      0.69       167
weighted avg       0.75      0.71      0.69       167
```

**Матрица ошибок (Confusion Matrix):**
```text
[[80  7]
 [42 38]]
```

* **Осмысленное сравнение:** Модель показала высочайший **Recall для класса Defect = 0.92**. Это означает, что пайплайн успешно отловил и изолировал **92% всего цифрового мусора** (80 из 87 дефектных фото), что полностью решает главную задачу пользователя по очистке памяти.

## 7. Анализ ошибок
Согласно матрице ошибок, главная уязвимость системы — **42 ложноположительных срабатывания (False Positives)**. Модель ошибочно отправила в папку `defect` 42 качественные фотографии.

* **Причина ошибок:** Слишком строгие пороги геометрических индексов EAR/MAR на третьем шаге. При анализе живых семейных эмоций (искренний широкий смех, прищуривание от солнца, крик радости) геометрия лица естественным образом деформируется. Модель MTCNN интерпретирует эти отклонения как брак мимики и блокирует ценные эмоциональные кадры.

---

## 8. Выводы
* **Что получилось:** Создана работоспособная, автономная и легковесная Pipeline-система на PyTorch, гарантирующая очистку 92% мусорных кадров. Реализован механизм изоляции сессий в папки `result_#` с автоматическим переименованием файлов.
* **Что не получилось:** Система работает избыточно жестко на кадрах с ярким проявлением эмоций.
* **Что можно улучшить:** Заменить бинарные отсечки на Шаге 3 гибкой **Score-системой (системой штрафных весов)**. Если фото четкое и центрированное, небольшие перекосы мимики не должны приводить к удалению кадра.

## 9. Код и воспроизводимость
Проект полностью автономен, не требует скачивания весов из интернета при инференсе и готов к упаковке в Docker.


### Инструкция по запуску:
1. Поместить исходные изображения для тестирования в папку `data/test/pipeline/` (разложив по подпапкам `correct` и `defect`).
2. Запустите последовательно ноутбуки: `pipeline_detected_family_image_human_model.ipynb`, 
3. `pipeline_detected_family_bluer_model.ipynb` и `pipeline_detected_family_image_app.ipynb`
